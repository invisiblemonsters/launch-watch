What we read on-chain

  • All eight core contracts listed in the app are verified (Sourcify exact match). None is a proxy: the EIP-1967 implementation, admin and beacon slots are empty, so the code cannot be swapped.
  • PermaLocker has no function that removes liquidity. Its state-changing functions are a one-time deployer initialize (already done), graduate, zapLiquidity, buyBackAndBurn and releaseBurn. That matches the site's claim that locked liquidity cannot be withdrawn.
  • Governance is in its owner-key phase. PermaGovernor.ownerKey() is 0xAD71…6533, a plain wallet (no contract code). It can run the governor's whitelisted actions directly, but never the treasury sweeps switch.
  • Holder voting opens at handoverAt() = Dec 2, 2026, 10:42 AM PST (fee manager T0 + 45 days; T0 was Oct 18, 2026, 11:42 AM PDT). The owner key keeps its powers alongside voting until T0 + 365 days, unless it steps down or holders vote it out (possible from day 90).
  • The same wallet is the service-settings key (PermaServiceSettings.key()). That key can pause new launches on the factory, but the code comments say it can never change coins that are already launched.
  • Score note: our scanner flags a withdraw(uint256) selector in the factory bytecode. In the verified source this is the factory calling WETH.withdraw to unwrap refunds, not a privileged rescue function.

Open questions for the team

  • Is the owner key / service key (0xAD71…6533) a hardware wallet? Is a move to a multisig planned? proposeOwnerKey/acceptOwnerKey already support a two-step handover.
  • Can you publish the governor's whitelist (target, function, tier) in plain language, so holders can see exactly what the owner key can change before Dec 2?
  • Is an outside review planned before holder governance opens?
