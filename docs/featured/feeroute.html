Feeroute on Robinhood Chain

Public fee vaults for Pons v2 creators on Robinhood Chain. A vault receives a token's creator fees and splits them by fixed shares (up to 10 wallets, optional vesting), and any change waits out a per-vault timelock. Anyone can sweep, and a bot sweeps hourly.

Team: @usefeeroute · Site: https://usefeeroute.com · Checked 2026-10-20 10:20 PDT · Not audited by a third party. The docs say "Beta, not audited" and describe an internal line-by-line review.

What we read on-chain

  • Scanned Oct 20, 2026. FeerouteFactory: 19/100 LOW. The only flags are a fresh deployer (2 transactions, first seen Oct 17) and a domain registered Oct 18. $FEEROUTE: 36/100 MODERATE. Drivers: Pons v2 curve liquidity around $4k, a launch wallet first seen Oct 19, and the new domain. No mint, pause or blacklist functions.
  • The factory has no owner() and no admin functions. createVault can only be called by a token's current Pons creator-fee recipient, and it checks that the curve is ETH-quoted. It is bound to the Pons v2 launch factory 0x7eD5…EC7e, matching the docs.
  • Vaults use Ownable2Step and ReentrancyGuard. Only ETH is split, and recipients that fail are credited, not dropped. The creator cap and timelock are fixed at creation.
  • The timelock is chosen per vault, from 0 to 30 days, so it is not one fixed value. The site's example shows 48 hours, and Explore lets you filter for vaults with the timelock off.
  • At block 93,604,758 the factory had created 0 vaults (no VaultCreated events). The $FEEROUTE token's Pons creator-fee recipient is still its launch wallet, not a Feeroute vault.
  • The docs list these limits themselves: the creator cap covers only the owner's own address; ownership transfer and rescueToken (ERC-20s go to the owner) have no timelock; fee flow after graduation to Uniswap v4 is unverified; and the Pons admin can reroute fees through Pons' own 72-hour timelock.

Open questions for the team

  • Will $FEEROUTE's own creator fees be routed through a Feeroute vault, and with what split and timelock? That would be the clearest demo for holders.
  • Could the $FEEROUTE token be verified on Blockscout or Sourcify? Today it only matches the Pons template bytecode.
  • The hourly sweep bot: which wallet runs it? Is its status shown on /status, and what happens to sweeps if it stops? Anyone can still call sweep().
  • Will the post-graduation (Uniswap v4) fee path be tested before the first routed token graduates?
  • Should rescueToken and ownership transfer go behind the same timelock as split changes in a later version, given the docs list both as known limits?
